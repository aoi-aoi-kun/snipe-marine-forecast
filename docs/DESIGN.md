# 七里ヶ浜沖の予報 — 設計説明

この文書は、アプリの目的・データの扱い・画面の考え方を、開発者以外にも伝わるようにまとめたものです。  
起動手順やデプロイ手順は [README](../README.md) を参照してください。

---

## 1. 何のためのアプリか

相模湾・七里ヶ浜沖で **スナイプ級ヨットの出艇判断** をするときの参考画面です。

| 見たいこと | このアプリが出すもの |
| --- | --- |
| これから数時間〜数日の沖の風と天気 | ECMWF の数値予報（3時間ごと・最大144時間先） |
| いま〜1時間のハーバー周辺の風 | 江の島ヨットハーバーの5分実況と、その延長（ナウキャスト） |
| 鎌倉市に警報・注意報が出ているか | 気象庁の公開データ |

### このアプリではないもの

- 気象庁の公式予報ではありません。
- ECMWF やハーバー運営の承認・提携を示すものではありません。
- ログイン・会員・データベースは使いません。全員が同じ公開データを見ます。
- **最終的な出艇判断は、現場の状況と気象庁の警報・注意報に任せます。**

## 2. 全体像（ひとことで）

```text
公開データ（ECMWF / enowin / 気象庁）
        │
        ▼
  Next.js サーバ（取得・集約・補正・学習）
        │
        ▼
  ブラウザ（日本語 UI・1画面）
```

ブラウザは `/api/forecast` を呼び、サーバがまとめた JSON を描画します。  
認証や外部 DB はなく、学習結果とキャッシュはサーバ上の `.cache/` にファイルとして残します。

---

## 3. 地点の考え方（いちばん大事な前提）

沖の予報とハーバー実況は **別の場所** です。数値をそのまま同一視しません。

| 名称 | 内容 | 座標 |
| --- | --- | --- |
| 七里ヶ浜沖（予報格子） | ECMWF IFS 0.25° の代表点 | 35.25°N, 139.50°E |
| 江の島ヨットハーバー | enowin の5分実況 | 約 35.31°N, 139.48°E |

両者の距離はおおよそ **6.8 km** です。  
補正（後述の MOS など）は「ハーバー＝沖」への置き換えではなく、過去のずれを統計的に寄せる倍率です。

---

## 4. データの出所

### 4.1 ECMWF 公開データ（沖予報）

- モデル: IFS、解像度 0.25°（おおよそ 25 km 升）
- 初期値: 00 UTC と 12 UTC
- 時間刻み: 3時間ごと、最大 144 時間先
- 主な要素: 地上10m風（u/v）、気温、雲量、降水量、最大瞬間風速（10fg / 10fg3）
- ライセンス: [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)
- 取得: HTTP で GRIB2 を部分取得し、eccodes の `grib_ls` で格子点の値を読みます

### 4.2 enowin（江の島ヨットハーバー実況）

- 出典: [enowin](http://enowin.japaneast.cloudapp.azure.com/)
- 間隔: 5分ごと（平均・最大・風向）
- 用途: 画面上部の「いま」、15/30/60分後のナウキャスト、MOS・急上昇パターンの学習材料
- 公開側が更新を止めると、画面上は「実況の公開が停止中」と出ます（アプリの不具合ではなく、元データの停止）

### 4.3 気象庁（鎌倉市の警報・注意報）

- 公開 JSON（神奈川県）から鎌倉市向けを抽出
- 画面上部に発表中の警報・注意報を表示
- 利用は公共データ利用規約に基づきます

API キーや申請は不要です。

## 5. 出艇の目安（ドメインルール）

アプリ内の「出艇不可能」は次のしきい値です（スナイプ運用の目安）。

| 条件 | 判定 |
| --- | --- |
| 平均風速 ≥ 10 m/s | 出艇不可能 |
| 最大瞬間風速 ≥ 13 m/s | 出艇不可能 |

- 沖予報の各3時間枠、およびナウキャスト（平均が 10 m/s 超）に適用します。
- ハーバー実況では、平均 8 m/s・最大 10 m/s 前後から注意メッセージを出します（出艇不可能ラベルとは別の早期警告）。

## 6. 処理の流れ

### 6.1 リクエスト時

```text
ブラウザ
  │  GET /api/forecast
  │  （初回・再取得: refresh=1 / 実況だけ: refreshHarbor=1）
  ▼
getForecast()
  ├─ ECMWF → 3時間枠に集約（天気・気温・風・瞬間）
  ├─ 気象庁 → 鎌倉市の警報・注意報
  └─ ハーバー実況
        ├─ ナウキャスト（15 / 30 / 60 分後）
        ├─ MOS で沖予報を倍率補正
        └─ 急上昇パターン一致時に直近枠を上振れ
  ▼
JSON を返す（Cache-Control: no-store）
```

フロントはページ表示時に実況を取り直し、表示中は約60秒ごと（タブが前面のとき）にハーバーだけ再取得します。

### 6.2 沖予報の集約

1. GRIB から格子点の時系列を取る  
2. 3時間窓ごとに平均風・瞬間・気温・降水量・天気をまとめる  
3. 天気の簡易ルール:  
   - 降水量 ≥ 1 mm → 雨  
   - それ以外で雲量 ≥ 80% → くもり  
   - それ以外 → 晴れ  
4. 瞬間風速は ECMWF の定義に従う（初期値から90時間先までは枠末1時間、それ以降は3時間の最大）

### 6.3 ナウキャスト（いま〜1時間）

1. 直近約30分の実況から風速・風向の傾きを推定  
2. 15・30・60分先へ延長  
3. 過去の「予測したあと本当はどうなったか」で減衰・バイアスを校正（過大評価を抑える）  
4. 校正データは `.cache/nowcast-calib.json` に保存

傾きが足りないときはナウキャストを出しません。

### 6.4 MOS（局地補正）

「同じ季節半・時間帯・似た風向のとき、ハーバー平均 ÷ 沖予報」の平均倍率を学習し、沖の3時間枠にかけます。

- 置き換えではなく倍率（上下限あり）
- 差がごく小さいビンは補正しない
- ビンキーは暖候期（4–9月）／寒候期（10–3月）×3時間帯×8方位
- 瞬間風速はハーバー最大 ÷ 沖 gust の別倍率（足りなければ平均倍率）
- 保存先: `.cache/mos.json`
- バックフィルはハーバー約30日・ECMWF 公開初期値（00/12UTC×約30サイクル、リード3〜36時間）＋ Open-Meteo historical IFS（約30日、欠けた valid time のみ）
- 型が足りないときは他季節の同型 → 近傍時間帯 → 全体平均（全体平均は沖へはかけない）
- **実況寄り**: いま〜約6時間先の沖枠に、直近ハーバー実況を重み付きでブレンド（`lib/harbor-blend.ts`）
- **補正の補正**: 適用倍率を \(f' = 1 + \lambda(f-1)\) に減衰。λ は全体に加え時間帯×風速帯でも学習（`.cache/meta-calib.json`）。急上昇も同様
- **沖への適用**: exact / hour / neighbor のみ（tier で減衰）。全体平均は学習用で沖枠にはかけない
- **実況停止**: 最新行が20分以上古いときはナウキャスト・急上昇マッチ・実況寄りを抑制
- **初期値差**: 直前の ECMWF 初期値との風速差を各枠の `cycleSpreadMs` に付与
- **リードタイム減衰**: 局地補正の λ に 12h/36h/72h で 1.0→0.7→0.4→0.2 を掛ける。急上昇補正は概ね36時間以内のみ
- **確度**: `confidence`（high/mid/low）を枠に付与。カードに「確度 高／中／低」を表示

### 6.5 急上昇パターン

過去の急な立ち上がり（例: 30分で平均がはっきり上がる）を覚え、似た前兆のときに直近の沖予報2枠を上振れさせます。

- 保存先: `.cache/harbor-patterns.json`

### 6.6 継続学習（サーバ起動中）

| 間隔 | 内容 |
| --- | --- |
| 約10分ごと | MOS・ナウキャスト校正・急上昇パターン・補正の補正（λ）を更新 |
| 約30分ごと（3ティックに1回） | 実況・予報キャッシュを強制再取得 |
| 約2時間ごと（クールダウン） | MOS アーカイブ＋Open-Meteo 突合のバックフィル |
| 約6時間ごと | ナウキャストの広域再学習（ハーバー最大約30日） |

- 起動は `instrumentation.ts` と API 呼び出しの両方から行います（Node ランタイムのみ）
- 各ティックでハーバー実況を再取得し、MOS / ナウキャスト / 急上昇 / λ を更新します
- `DISABLE_CONTINUOUS_LEARN=1` で止められます
- Docker / Render では `.cache` をボリュームに載せ、再起動後も学習が残ります
- `/api/health` でキャッシュ書き込み可否と学習件数を返す。`?warm=1` は外部 cron 向け（約6回に1回フル更新）。`?full=1` で毎回フル
- プロセス内 keep-alive（既定約8分、`KEEP_ALIVE_URL` / `RENDER_EXTERNAL_URL`）は起動中のスリープ抑制用。眠ったあとは外部 ping が必要

## 7. 画面の構成

1画面・認証なし。上から重要度の高い情報です。

```text
┌─────────────────────────────────────┐
│ 鎌倉市の警報・注意報（あるときだけ）   │
├─────────────────────────────────────┤
│ 江の島ヨットハーバー                   │
│  いま / 15分後 / 30分後 / 60分後      │
│  （折りたたみ: 補足・ナウキャスト説明・学習）│
├─────────────────────────────────────┤
│ 風と天気（全体グラフ）                 │
│  （折りたたみ: 図の見方）              │
├─────────────────────────────────────┤
│ 日ごとの3時間カード                    │
├─────────────────────────────────────┤
│ この予報の読み方（折りたたみ）         │
│ 出典・ライセンス（フッター）           │
└─────────────────────────────────────┘
```

### デザイン上の方針

- **データが主役**: ヒーローや販促コピーは置かない
- **説明は折りたたむ**: 補足・学習状態・図の見方・読み方はデフォルトで閉じる
- **矢印は「風が向かう向き」**: 気象の「風向（どこから吹くか）」を 180° 回転して表示。上が北
- **単位は m/s**: ノット表示はしない
- **モバイルとデスクトップの両方**で読める1カラム構成

## 9. デプロイ上の注意

- `grib_ls` が必要なため、**サーバレス（例: Vercel の短い関数）より Docker 常時起動**が前提です。
- 推奨の公開先は Render（`render.yaml` あり。`healthCheckPath: /api/health`、Disk で `.cache`）。
- 無料枠はスリープします。精度を保つなら外部から `/api/health?warm=1` を定期 GET してください（README 参照）。
- 学習を残すには `.cache` の永続ディスク／ボリュームが必要です。

## 10. 第三者への短い説明（コピペ用）

> 七里ヶ浜沖のスナイプ出艇向けに、ECMWF の沖予報（3時間・最大6日弱）と江の島ヨットハーバーの5分実況を並べる Web アプリです。直近1時間は実況の傾きからナウキャストし、沖予報はハーバーとの過去のずれで局地補正します。気象庁の鎌倉市警報も表示します。公式予報ではなく参考画面で、ログインも DB もありません。
